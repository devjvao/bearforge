Reviewed `main` at `27ff3a1e729490a9111ac2afa7fc48ee11e820ce` on 2026-11-27. The review identified **17 findings** and one intermittent test failure to investigate. Address the five P1 findings first. They concern user files, Git history, remote identity and saved credentials.

### Import timeout investigation

The fixture sends its first clone signal after a real local clone and an origin configuration command. Delaying that signal by 5.5 seconds reproduced the old five-second failure before the test edited the catalog. The revised harness waits for the requested event, importer completion or the test deadline. An injected early importer failure reported the phase and error immediately. The delayed run passed with the fix, and the formerly failing subtest passed three Windows race runs under package concurrency. The original run did not record enough information to identify what delayed that particular clone.

Linux integration testing also reproduced an existing Git 2.43 failure on the reviewed commit. During an offline update preview, Git reports a missing promisor parent differently on this version. The ancestry check now confirms the reported object is absent from the local object store and defers the update. The regression verifies that preview sends no request for the parent. A separate Git 2.43 fixture verifies that removal distinguishes a private ref named `COMMIT_EDITMSG` from an ordinary commit message.

## P1 — address first

- [x] **1. Remove only an empty directory during whole-workspace cleanup.** After deleting the manifest, `RemoveEmpty` calls `os.Remove`. An empty registered workspace whose directory was replaced by a regular file can therefore lose that file and report `removed`. Make `RemoveEmpty` use a directory-only OS removal primitive at the point of deletion. Its other callers also create directories for clone receipts and folder ownership markers. Preserve the existing `container_retained` result when an unexpected entry remains. Extend `TestWholeRemovalPreviewAndRetainedContainer` to check the file's bytes after confirmation, including replacement between preview and apply. Check that genuine empty directories, clone receipts and folder markers still clean up. [Removal caller](../../../internal/app/removal.go#L307) · [Storage primitive](../../../internal/config/store.go#L72) · [Existing regression fixture](../../../internal/app/workspace_plan_test.go#L150)

- [x] **2. Preserve private Git history before removing an intact checkout.** The healthy-checkout path enumerates HEAD and the new OIDs reported by `git reflog show --format=%H HEAD`. A commit retained only on the old side of a surviving reflog entry can lose its last reference when Git removes the registration. Private ORIG_HEAD and FETCH_HEAD objects also escape this inventory. Reuse the missing-checkout code that understands both reflog backends, preserves recoverable objects, and refuses unknown private refs. Run intact-checkout variants of the old-only reflog, FETCH_HEAD/ORIG_HEAD and unknown-private-ref fixtures. An unknown private ref should block removal before the registration changes. After removal and garbage collection in the disposable fixture, the retained objects must resolve and the unrelated shared reflog object must remain unanchored. [Removal sequence](../../../internal/app/removal.go#L257) · [Intact history reader](../../../internal/gitcli/worktree.go#L263) · [Private history reader](../../../internal/gitcli/missing_root_refs.go#L45) · [Reflog fixture](../../../internal/gitcli/private_history_test.go#L90) · [Private-head fixture](../../../internal/gitcli/missing_root_refs_test.go#L10)

- [x] **3. Validate the remote URL that Git will fetch.** For a remote with two URLs, the single-key reader and batched reader both accept the last value. Git fetch selects the first. A catalog match on the last value can therefore permit a fetch and prune from a different repository. A disposable local repository returned the second URL from `git config --get` and the first from both `git remote get-url` and `git ls-remote --get-url`. Use a dedicated reader for the first configured fetch URL across single, batched and fallback paths. Route sync, PR routing, clone recovery, credential rebinding and auth status through it. Preserve generic Git config lookup semantics, intentional URL rewrites and separate push URLs. Update the existing last-value expectation. Assert that a mismatch stops sync before any ref changes for one and multiple catalog remotes, including values from Git config includes. Add a credential-rebind or PR-routing test using the same two-URL fixture. [Identity check](../../../internal/app/service.go#L285) · [Git readers](../../../internal/gitcli/client.go#L303) · [Fetch and prune](../../../internal/gitcli/client.go#L401) · [Rebind check](../../../internal/app/repository_rebind.go#L167) · [Current test expectation](../../../internal/app/status_git_test.go#L103) · [Git fetch URL selection](https://git-scm.com/docs/git-fetch#REMOTES)

- [x] **4. Keep token input hidden on an attached terminal.** `auth login --token-stdin` promises echo-free input but uses the ordinary line reader even when the input is a terminal. Typing or pasting a token can display it. Use the existing hidden-input machinery for terminal stdin and keep bounded line reads for redirected files and pipes. Exercise a synthetic token through the public CLI in a PTY or native console. Check the transcript, restoration of terminal settings after success and cancellation, and existing piped-input behavior. [Token input selection](../../../internal/cli/auth.go#L108) · [Flag contract](../../../internal/cli/auth.go#L159) · [Hidden reader](../../../internal/cli/auth.go#L242)
